## 阶段 1：播放核心（M1，FR-01~06）

> 本阶段无播放列表，通过「打开单个文件」方式验证播放能力；⌘O 多选入列表在阶段 2 接入。

### 步骤

- [x] **1.1** `src/shared/types.ts` 共享类型；主进程注册 `media://` 自定义协议（仅限显式加入的白名单路径，技术文档 §5）；`openFiles` IPC 通道（单选，阶段 2 改多选）
- [x] **1.2** `Player` 类封装 `<audio>`：`load/play/pause/toggle`（FR-01）
- [x] **1.3** 控制栏播放/暂停按钮，图标随播放状态同步（FR-01）
- [x] **1.4** 进度条：当前位置/总时长 `mm:ss` 显示，支持点击与拖拽跳转；`timeupdate` 节流 ~250ms（FR-02）
- [x] **1.5** `seekBy` 快进/快退，钳制到 `[0, duration]`；步长暂用默认值常量 5 秒，阶段 3 接入设置（FR-03）
- [x] **1.6** 音量滑块（0–100%）+ 静音切换与视觉标识；音量加减逻辑封装为独立函数供阶段 2 快捷键复用（FR-04、FR-05）
- [x] **1.7** 播放速度档位切换 0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0，默认 1.0（FR-06）
- [x] **1.8** Vitest 单元测试：`seekBy` 边界钳制（负值、超时长、无时长）

### 验证

- [x] 用样例 MP3（本地无素材时可用 ffmpeg 生成）验证：播放/暂停切换正常（2026-08-27 用户确认）
- [x] 进度条拖拽/点击跳转准确，时间显示格式 `mm:ss`（2026-08-27 用户确认；自动测试中 seek 到 100s/300s 均准确）
- [x] 快进退在文件首尾不越界（`clampSeekTime` 单元测试覆盖：负值、超时长、无时长）
- [x] 音量滑块与静音行为符合 FR-04/05；速度各档位生效（2026-08-27 用户确认）
- [x] `npm run test`（Vitest）与 `npm run typecheck` 通过（8 tests passed，2026-08-27）
- [x] 提交入库，commit message 注明对应条目（如「实现 FR-01~06」）

> 过程记录：期间修复「播放约 1 秒中断」问题——根因是 `media://` scheme 权限缺 `standard: true` 导致媒体管道重发请求后中断，且需显式 206 + `Content-Range` 才能使 `seekable` 生效；结论已记入技术文档 §5。
